09 · The evaluation system

Two evaluation systems. One builds the prompts. One checks every draft.

Evaluation system 1 before release

How we build and improve the prompts

1Change a prompt or a rule→2Run 46 test cases→3Judge every run→4Compare with the last build→5A person decides what ships

Run by hand. Never during a pastor's call. 20 immigration, 8 hospital, 18 hostile

Judges: plain code, Jev, outside AI reviewers, a person.

Jev, a decision API from TypeSafe (not a chat model), is used in both: as a judge of whole test runs, and as the live second check.

Evaluation system 2 while a pastor uses it

How we check every draft

1Claude writes a draft→220 named rules and a safety floor→3Jev answers yes or no questions→4Fails: rewrite, up to 3 tries→5The pastor approves, edits or stops

Runs on every draft, before the pastor sees it. Jev answered 239 of 239 calls in the scored runs

About 20 s, 2.5 words per second. Criterion: Technical Execution and Use of AI. Say: "We built two evaluation systems. The first runs before release, by hand: we change a prompt, run 46 test cases, judge every run, compare with the last build, and a person decides what ships. The second runs on every draft while a pastor uses it: named rules, then Jev's yes-or-no questions, then up to three rewrites. Jev is a decision API from TypeSafe, not a chat model, and it works in both." Jev checks every draft

How it works (run time)Claude writes. Named rules check. Then one call to Jev asks yes or no questions about the draft. At its line (0.50, or 0.60 for the facts question) it is rejected and rewritten, up to three tries, then the pastor takes over.
What Jev seesTokens, not names. A leak test sent 15 canaries and found none.
If Jev is downThe pastor is not blocked. The draft goes on under the plain-code checks, and the log says so.
SpeedAbout 150 ms a call, about 1 second added to a case. Jev costs about $0.0004 a case ($0.042 per million input tokens).
The lines0.50, and 0.60 for the facts question, a line we set after seeing the data. On 20 real draft pairs: safe 0.02 to 0.35, unsafe 0.78 to 0.99. Not a calibration study. Not perfectly repeatable: the same drafts moved by up to 0.12.
What went wrong liveIn a grief case at 0.50, Jev rejected a safe triage three times (0.85 to 0.88) and the stage escalated. With the crisis type given and the 0.60 line it completed, but triage scored 0.59, one hundredth under the line. False-reject rate over many cases: not measured.

Live on three scenarios. Pastor edits are not checked. TypeSafe's terms and retention for this use have not been reviewed.

Evidence: documents/TECH_CLAIMS.md rows 50 to 55; evaluations/validation/JEV_GATE_VALIDATION.md; code/nury/jev_gate.py. A per-question line (a higher line for the facts question) is being added by hack-jedi and is not built yet: do not claim it. Informed by case-management practice

  • Nury is informed by case-management and trauma-informed practice: it gathers the facts, makes a plan, leaves every decision to the pastor, and saves a record.
  • It is a drafting aid, not a professional case-management system, and no standards body has endorsed it.
  • We know the gaps: case status with dates, an access log, and sign-in. A consent note is in the app, and nobody has reviewed it against a standard.

We read the NASW standards for social work case management (2013) in full. We did not map CMSA's standards (members only) or SAMHSA's sixth principle: we could not verify them.

Backup only; not in the 3-minute talk (Sensei's decision). Source: documents/STANDARDS_ALIGNMENT.md, with every quote checked against the text I read.
